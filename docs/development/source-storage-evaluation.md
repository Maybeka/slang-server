# 局部查询源码生命周期与实际计量

本阶段基于 main `643328d198708e9acca67b19fe3488b7bcb28e4b`，资格二进制 SHA256 `e8ecca84a5416985838957f0572282e65ba277a2f51c06fa817c8700cc13bf26`。五类总目标仍 active；本阶段落实第4类中的私有查询源码计量与消费者释放，实验仍默认关闭，无新增固定防抖。

## 改动与所有权

`assignQueryText` 的文本此前只由源码位置表持有，既没有进入旧文件缓存计量，也不会随局部语法树释放。现在以弱索引对实际存活的 FileData 去重，计入分配容量、行表、名字、路径和索引；被替换但仍被消费者固定的旧文本也可见。`sourceMemory` 命令状态单列 queryBytes/queryBuffers，源码位置表另计。这是保守的容量计量，不是进程 RSS。

三个私有解析入口改用 QueryText。当前局部 AST、原生诊断基线的私有文本、后续方法宏证明均由语法树租约持有；树和 compilation 的最后消费者退出后释放文本。独立 checkpoint/导出树通过 retainBuffers 固定同一租约，先于租约取得的 pin 也能在最终退出时完成释放。取消和异常解析遵循同一生命周期。

不会复用 BufferID；宏名字和调试名字继续由 SourceManager 保持。普通磁盘/编辑器文件和不可变前缀不经过私有文本释放路径。释放清除对应的行指令和诊断 pragma；快照仍可重放不相关 Native 图，私有或已释放的根不能写入持久化解析档案。

完整计量会改变极小预算下的准入判断。测试没有提高预算：要求较小的新参数变体实际被构建、诊断与 Native 一致并维持原预算上界；若消费者仍固定旧后代，允许正确拒绝新 owner。关闭固定旧后代的消费者后，同一注册表、同一预算必须实际复用较小变体，不清空拒绝建议。

释放后源码位置表仍保留身份，表容量、普通全设计源码以及仍有效的固定 owner 仍需预算/代际回收。本轮不能据此宣布第4类完成，也不能把全部 RSS 差值只归因于文本释放：完整计量也影响基于当前源容量的自然回收阈值。重复取消回收的自适应重试、旧/新候选峰值、可配置 source budget 仍待实施。
