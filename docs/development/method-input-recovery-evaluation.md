# 依赖变化后的原生回退重载

本阶段是五类总目标中的正确性补齐：局部证书已经观测到依赖变化时，原生回退必须读取新内容。总目标仍 active；后续宏重绑定、外部引用闭包、完整语义取消和内存回收仍待实现。此前的[认证降耗报告](native-diagnostic-reuse-evaluation.md)保留为性能优化阶段的证据。

## 问题和实现

之前完整内容证明能够拒绝局部结果，但随后原生路径可能复用旧 SourceManager 的依赖缓存。监视通知尚未到达时，会出现“已拒绝复用却仍返回旧类型/诊断”的情况。

现在使用明确的输入变化状态，证书释放后仍保留重载义务。查询或后台分析构建私有原生 driver，重新加载磁盘配置和最新未保存文本；取消前不提交新上下文，也不清空旧发布图。无效配置令语义请求失败，直到能构建有效替换；状态和显式维护命令仍可用。后续增量通知先同步一次文本，再重试重载，不重放已应用的范围。

首证书还对照原生上下文实际读取的源和命令文件内容。配置加载保留 workspace/user/local 三层的原始字节及缺失层，供认证检查；这些运行时见证不进入客户端 JSON 或配置 schema。防止配置/文件列表在首次认证前改变后，证书把新读到的内容误认为旧语义的依据。

没有增加开关或固定防抖；原有实验开关继续默认关闭。指定冻结库仍遵守依赖固定、手动重建的约定。本修复处理局部证明已经发现的变化，不把整个文件系统变成原子快照，也不替代普通原生模式的 watcher 协议。

## 正确性验收

小型测试覆盖同长度同 mtime 依赖变化、首次认证前源/文件列表/配置修改、原先不存在的 local 配置创建、无效配置、四个取消检查点，以及取消后继续部分范围输入。测试文本检查通过当前 driver 获取文档，避免在 driver 替换后访问仍由旧测试句柄持有、但 SourceManager 已释放的文档。诊断 oracle 辅助函数恢复原始配置的完整字节。

在原始 CVA6＋完整 core-v-verif 场景中保留整个 404 实例 DUT 和 UVM 冻结，增加一个不在冻结契约中的可变探针 package。类型从 `[7:0]` 改为 `[9:0]`，保持长度和 mtime，不发送 watch 通知。旧二进制返回 8 位，完整诊断图也不匹配新建 Native；新二进制返回 10 位，全部 613 URI 诊断图与全新原生分析一致。重载悬停约 1458 ms，属于完整上下文重建，不能作为快速局部查询耗时；旧版错误回答约 676 ms，全新原生已预先建好上下文后的查询约 0.43 ms，三者不是可比的速度排名。

普通场景仍是原始 612 URI；42 个公共状态验证两种查询顺序、悬停、补全、resolve、定义和宏三种展示。802 CTest、17 Python、43 transport、40 相关 case/4357 断言通过；另有配置见证不公开的测试和 schema 检查。默认 UVM 使用 shippedPreparse，外置 UVM 命中项目缓存，两者均零语法解析，整个 DUT 根 retained 命中，无 namespace decline。SDK clean archive＋patch 的 709 文件逐个一致。未修改 SDK 算法或冻结实现，保持原 gitlink。

## 性能与内存

基准为 `df924eda86db666304fbe344f7d19bede0662868` 的已验收安装。新旧两臂使用同一物理 UVM、相同冻结设置和相同实验；Native oracle 只关闭 body 实验，仍保留已验收的冻结层。输入按 100 ms 独立发送，包含不完整文本；无 trace/RSS 探针的延迟与内存探针分开。前三对暖态有几毫秒差异，其中一对与仅测试目标的构建重叠；保留该数据，并追加三对空闲、反转顺序测试，总计六对，不删除负结果。

下表单位 ms，短序列为轮次中位，长序列为末次值。

| 场景 | 末次 hover：旧→新 | 末次诊断：旧→新 |
| --- | ---: | ---: |
| 合格首次单次（3轮） | 40.59 → 41.12 | 65.57 → 65.56 |
| 暖态连续输入（6轮） | 26.72 → 25.99 | 38.60 → 38.13 |
| 原始多行 get_name＋后续宏（1轮） | 25.42 → 19.99 | 934.32 → 877.34 |
| 全局宏回退（1轮） | 1045.54 → 880.30 | 1378.53 → 1203.83 |
| 1008输入（单轮，无探针） | 21.42 → 30.55 | 32.68 → 42.02 |

1008 输入两臂均全部成功，查询 p50/p95 为 18.04/22.21 → 19.53/25.36 ms，末次诊断为 32.68 → 42.02 ms；这轮长会话存在小幅负差值，不能宣称全部性能指标改善。独立 trace/内存会话则 p50 25.94 → 25.67 ms、p95 43.61 → 29.66 ms，完整文件证明中位 8.26 → 8.10 ms，context 证明均约 0.027 ms。六对短暖态的 hover、诊断中位基本持平。测量未固定 CPU/调度条件，不能仅据这些差异归因于某一新增检查。本阶段不宣称新增性能收益；原始多行场景仍需约 877 ms 原生诊断，继续作为局部闭包的主验收场景。

单序独立内存会话（20 ms 采样、3 GiB/180 s 预设会话保护）RSS 峰值 1542.23 → 1545.58 MiB，physical footprint 1147.42 → 1151.11 MiB；无内存收益。重复取消回收候选的问题仍存在，第 4 类保持待办。所有成功公共结果及终态诊断图均匹配 Native，delta 模式空闲无重复发布。
