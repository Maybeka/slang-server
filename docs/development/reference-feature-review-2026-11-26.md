# 参考实现的功能与测试评估 · 2026-11-26

参考实现指 Hudson River Trading 的 slang-server。官方 slang 指 Mike Popoloski 维护的编译器。此次评估沿用上次确定的 49 项更新，截止参考实现 `1b413a4`。依据提交说明、测试输入、断言、夹具和预期输出判断功能价值；没有将两份 server 产品代码进行差异比对。

39 项直接修改了参考实现的测试或夹具，10 项没有。表中数字是该项修改的测试路径数，含共用测试工具和预期输出文件；同一路径可出现在多项更新中。依赖指针变更可能另带 SDK 内部测试。仅更新预期输出时，应先解释语义变化，再决定本项目的预期值。

“修复”是排期建议。本次升级只改编译器集成。4 项列入修复、5 项确认存在功能缺口、12 项需要优先验证。其他 28 项包括 13 个候选、4 项只取场景、1 项按本地需求适配、1 个可选保护、7 项延后及 2 个发布编号跳过。

## 先做哪几件事

1. **先修配置重载时遗漏的源码事件（#652）。** 通过本机 LSP 新建模块，正常配置下立刻能查到；配置无效时同一操作查不到，修复配置后才出现。验收应同时检查旧设计仍可用、新文件可发现、打开的未保存文本具有优先权。把 #650 的删除/重建和 #651 的分析中新增依赖纳入同组验证。
2. **修未知请求没有标准应答（#607）和词尾查询（#649）。** 本机先发未知请求，两个后续状态请求均正常返回，间隔约 250 ms，期间未见未知请求的响应。词尾试验对同一信号在词内高亮 2 处，词尾和空格后均为 0；目标为 2、2、0。
3. **保留 #592、#644、#654 的验收意图。** 使用 #592 的夹具，经真实协议分别在普通源和 `-v` 库文件模式选择 `top.selected`。空白编辑后 0 错，写错字段恰好 1 错，修正回到 0；单独打开文件仍报告默认 logic 的成员错误。这里已经满足可见诊断要求，内部合成作用域及切换多个实例仍应单测。#644 在现有代码有缺省 context 处理。#654 采用本项目更严格的双文件保存与完整宏语义验收。
4. **独立修复 #627 的包成员补全。** 使用参考测试原文比较旧版和本次 v12.2 server，两版均无源码错误；两版的 facade:: 都多列了未导出的 HIDDEN，relay:: 漏掉应可见的 OFF，还多列了 HIDDEN。这是已复现的编辑器缺陷，升级编译器后仍需修复。
5. **把其余 SDK 相关行为并入 v12.2 验收。** 先测包再导出、泛型/虚接口、generate、宏和错误恢复。把候选 SDK 的完整分析作为其局部更新和冻结模式的语义对照。SDK 切换和功能修改分别提交，便于定位回退。

还用两版 server 重放了 #546、#556、#579、#593、#629 的参考用例：五项均存在可观察的功能缺口，具体位置与预期在对应条目。

表中 49 项均给出了参考测试或缺口、处置理由和本地入口。已有本地入口只说明验证位置，表内标为候选的行为仍需专门复现。对 #607、#627、#644、#649、#652、#654 又用迁移前后两份 Mac server 做了相同的协议试验，两份构建都含本地性能默认值调整。#644 均返回 some_signal；#654 首次打开和保存后两个模块各保留 1 个错误，修复已打开模块后变为 0 和 1。其余条目中引用的单版本探针是迁移前的记录。探针测试的是公开的协议结果。其他事项的处置依据需求和测试审读，表内“优先验证”表示仍需本地复现。[升级前评估数据](../../validation/data/official-slang-v12.2-assessment-2026-11-26.json) · [两版协议实测](../../validation/data/official-slang-v12.2-upgrade.json) · [官方 slang v12.2 评估](official-slang-v12.2-assessment.md)
