# 固定库引用变化的局部诊断复用

本阶段扩展局部诊断对固定 provider 引用变化的支持。实验继续默认关闭，无新增固定防抖。五类总目标 active；一般引用闭包、后续宏行号、完整语义取消和通用内存回收仍未完成。前阶段[重载修复](method-input-recovery-evaluation.md)、[认证降耗](native-diagnostic-reuse-evaluation.md)继续生效。

## 证明与边界

以前方法改变外部 read/write 引用状态就回退原生诊断。现在，若变化的 bit 在用户指定固定库首次导出时已经成立，则增删这个用户侧引用不会改变全设计使用状态的 OR 结果。提供者只取当前 driver 的 trusted UVM/scope library。SDK 只读 getExportedReferenceUsage 查询原始导出 profile，不混入后来的导航/消费者 overlay，不强制绑定或创建快照。普通实例函数如 UVM get_name() 可以因此局部更新；无固定库或库内原先未使用的引用仍保留原生路径。

引用状态不能代替副作用分析。新增/移除 package/static/task/constructor 调用引用仍要求 Native effect analysis；记录真实目标及 extern prototype，递归访问 receiver/实参，防止安全实例调用或系统调用包住另一个调用而绕过限制。原有 initializer、driver、时序、特殊化、局部声明、非局部诊断和错误上限检查保留。

边界测试促使两次收紧：先确认 procedure driver 检查不包含所有 transitive package 写入，再修复自定义 AST visitor 默认停止递归的问题。早期样本的 Native 图仍一致，但缺乏预期的保守准入。最终矩阵覆盖 package 纯读/全局写，以及 direct/member/system 三种嵌套形态，全部明确回退。初始两个原型目录不纳入最终资格。
