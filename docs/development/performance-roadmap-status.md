# 性能优化路线

## 目标与约束

优先泛化 UVM 与 RTL 冻结和增量编辑。固定 provider 与可编辑 consumer 分文件，固定依赖变更后手动重建，并保留未保存文本。语法前缀、固定 scope 和 UVM 语义缓存启用后默认不限额，显式限额仍可用。实验默认关闭。

随包提供一套默认 UVM 预解析结果，其他配置使用项目侧缓存。语法预解析与进程内的语义对象复用分别处理。

## 实施顺序

1. **先守住原生回退基线。** 分别跟踪 UVM、RTL 冻结和局部更新的拒绝点，以及从拒绝到本版本查询或诊断就绪的完整路径。优先消除重复的输入证明、解析、绑定和诊断收集。必须回退时，使端到端耗时达到原生水平，再优化冷启动、结构调整和内存峰值。
2. **泛化冻结。** 按语义依赖、绑定上下文和对象所有权判断范围，优先复用原有语义对象。支持 package、module 和指定 RTL 层次。父层依赖无法闭合时，保留可独立复用的子层次。
3. **扩展增量编辑。** 让重绑、查询和诊断沿实际受影响的依赖更新。先扩大函数和任务内部的覆盖，再处理影响边界明确的结构修改。

每个扩展保留最小正例、拒绝反例和原生结果对照。核对查询、完整诊断、编辑版本和恢复过程。性能对照按相同版本、输入和编辑序列进行，明确区分进入实验、拒绝回退和实际复用。大型工程按需运行，详细验证记录留在本地。
