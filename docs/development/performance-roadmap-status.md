本轮三轮中位：合格首次单次 hover 93.72→42.62 ms、诊断 232.12→67.70 ms；合格首次连续编辑末次诊断 172.41→36.54 ms；暖态 hover 37.06→25.94 ms、诊断 56.54→38.07 ms。首次诊断机制认证约 121→14.5 ms，单次完整文件证明约 15.50→7.23 ms。旧多行前缀同时新增 get_name 引用并影响后续宏，首次诊断仍约 845 ms，作为第 3 类主验收场景保留。

普通千次输入两臂均全成功，查询 p50/p95 32.82/59.39→24.74/32.36 ms，末次诊断 45.93→31.65 ms。所有成功查询及 612 URI 终态图匹配 Native。

内存没有宣称改善：正序 footprint 1340→1517 MiB，反序 1513→1465 MiB；RSS 两序峰值基准 1386～1402 MiB、候选 1412～1434 MiB。回收候选取消 284→365、274→356，两序各成功一次。多次取消时 source charge 固定在约 32.85 MB，给第 4 类提供了“同一计量值下反复准备”的明确切口；同时需补齐 query 数据计量，不能据该值断言全部源存储不再增长。

下一实现阶段推进第 3 类：先把后续宏方法纳入局部诊断集合，再建立新增/移除引用的来源账本和受影响声明闭包。第 1 类原子语义段、第 4 类回收浪费与峰值继续作为独立验收项，总目标尚有这些工作待完成。
