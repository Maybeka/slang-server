# 回收维护重试与前台响应

阶段基于 main `7744867c5eca52af4422d77c7e5c7c037bbcf75d`，测试二进制 `47dc36b995c5109d27ff92de5b47029f346bd4450ed70335da7609e6c97bf163`。总目标仍 active。实验默认关闭，正常输入、查询和诊断没有新增固定防抖。

## 实现与边界

原先旧回收候选被新输入取消后，只要下一次队列空闲就立即重建；CVA6千次输入中可重复约280次。现在根据取消前实际耗时计算指数重试等待，每次等待上限1秒；失败后的期限随后续前台活动后移，连续操作期间减少重试。停止操作后期限自行到达，不需要再来一次输入触发。

只有纯回收维护进入该等待。新输入/查询、当前诊断、输入或配置恢复和异步结果唤醒优先处理；JSON-RPC条件等待同时接受队列输入、EOF和异步wake。原先两倍源码触发阈值的硬上限继续绕过维护等待；预算没有提高。成功替换、epoch变化、低于触发阈值、关闭功能及失败配置均清理重试状态。

这仍不能中断已经进入的完整模型/语义原子段。硬上限下的同步路径也未改为可中断；后续继续处理owner取消传播和完整语义/模型中的阻塞。
