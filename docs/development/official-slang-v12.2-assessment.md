# 官方 slang v12.2 升级评估 · 2026-11-26

以下记录升级前的评估。评估时的 main 为 `97260665f39f13a5effdc619ede03c8effaf0fc1`，使用官方基点 `31a29606b5fb7a50a68bd07fddef4458abd83f53` 和本项目补丁。正式标签 v12.2 指向 `1130e4d42f799d2915b3253dfa9ff429f8cd3e14`，比该基点多 122 个可达提交。SDK 准入可独立于参考实现。下文的试配数据以当时的基点为对照。[官方发布说明](https://github.com/MikePopoloski/slang/releases/tag/v12.2)

## 迁移结果

升级代码提交为 `cf2d2fdeed0b9b0520c0408b4c2c15f1b4c95a76`。新补丁可在干净的官方 v12.2 上应用，742 个 SDK 文件逐一核验，重复运行准备步骤也通过。下表保留升级前的判断，实际构建、测试和项目样本数据见[升级验收记录](../../validation/data/official-slang-v12.2-upgrade.json)。

**诊断的归属。** v12.2 为 `Compilation` 新增了可嵌套的 `DiagnosticCapture`。对已展开模型临时绑定表达式时，捕获期间产生的诊断进入当前捕获对象自己的集合。调用 `finish()` 返回合并后的诊断并恢复上一层，直接离开作用域则丢弃本层结果并恢复上一层。普通编译仍写入主诊断集合。项目补丁在这个普通写入路径为 RTL 实例体维护诊断引用，用于认证和跨编辑重放。因此在共同的禁用、未实例化分支过滤之后，活动捕获直接写入私有集合并返回；只有普通路径才更新主诊断集合、错误计数和可用的复用索引。[官方 API](https://github.com/MikePopoloski/slang/blob/v12.2/include/slang/ast/Compilation.h) · [适配后的实现](../../external/slang/source/ast/Compilation.cpp)

新增回归在索引已建立时触发内外两层捕获，丢弃内层并取回外层。测试验证错误计数和索引未增长，让下一版设计实际导入该 RTL 实例，检查重放后没有临时错误，再追加一条普通错误，确认错误计数和索引各增加一次。该用例共 12 条断言。[跨编辑回归](../../tests/cpp/CertificationIndexTests.cpp)

**全量测试发现的额外语义变化。** 项目字符串宽松转换仍拒绝 event、real 和动态数组。官方 v12.2 允许字符串拼接中的零次重复项贡献零长度，并要求格式化字符串剔除 NUL 字节。`$sformatf("%c", 0)` 的结果与空串字面量相同，作为 RTL 参数可以复用。SDK 回归保留三种非法操作数的错误断言，并新增常量值断言；冻结测试同时断言原生模型与复用模型的参数值和再次编辑时的命中。[零次重复修正](https://github.com/MikePopoloski/slang/commit/52adb0492) · [格式化字符串修正](https://github.com/MikePopoloski/slang/commit/aa6dd8cbe)

**构建、分发与缓存。** 独立检出升级提交后，Release 全量 CTest 通过 1,109/1,109；含本地性能默认值的工作区通过 1,110/1,110，多出一项预算默认值测试。两种构建均通过 17 项 Python 测试，以及方法体查询、解析次数和过期诊断发布验收。传输测试通过 43/43。实际安装目录只含 `default.cst`，安装后的 server 报告直接使用默认制品，语法解析 0 ms。指定外部 UVM 的同一项目保留旧缓存时，v12.2 首次生成自己的缓存，重启后命中。

## 补丁适配工作量

项目补丁涉及 119 个文件；两个官方基点间有 171 个文件变化，与补丁重叠 47 个。直接应用有 16 个文件无法匹配。使用项目补丁的基底对象做三方应用，110 个文件自动处理，剩下 9 个文件、10 个冲突块。5 个是实现文件，各有一处冲突，4 个是 SDK 测试文件。此次官方区间中，顶层 CMake 主要改动是版本号，SDK 的 external 依赖声明文件没有差异；无需根据大版本号推断所有依赖都要更换。

| 实现文件 | 建议如何处理 | 通过条件 |
| --- | --- | --- |
| Compilation.cpp | `DiagnosticCapture` 可嵌套，在局部捕获期间写私有诊断集合。普通路径继续更新本地诊断顺序、去重和 RTL 实例体复用索引。该 API 作用于已展开模型，`addDiag` 仍有未冻结的前置条件。 | 嵌套捕获、取消与恢复后，公共发布集合及版本准确；临时诊断不进入下一次增量重放；只读冻结对象保持只读。 |
| SourceManager.cpp | 保留项目对源缓冲的生命周期管理；首次生成行偏移时，在取得写锁后再次检查缓存，只计算一次。 | 并发首次行号查询结果一致；替换缓冲、宏展开和旧快照的位置仍有效。 |

4 个测试冲突分别在 FileTests、HierarchyTests、PreprocessorTests、VisitorTests。需要同时保留官方的并发行号、嵌套模块、嵌套宏和改写后的默认 net 类型用例，以及本项目的源码快照、取消、宏状态记录和端口元数据用例。自动合并的重叠文件仍需验收，重点覆盖 Lookup、Type 和 Scope 的行为。另需验证项目补丁中 ParameterBuilder 创建的参数能被正确冻结和复用。

**已做的编译探针。** 在临时 SDK 中按上表组合五处实现，重新生成候选版本的诊断头，关闭旧预编译头，复用本机 Release 的编译参数，对 6 个 SDK 和 6 个 server 翻译单元执行 `clang++ -fsyntax-only`，12/12 通过。覆盖 Compilation、SourceManager、AnalysisManager、DefParamResolver、SourceLoader、SyntaxTree，以及 driver、浅层分析、server compilation、方法体诊断、发布客户端和 UVM。此结果降低了接口迁移的不确定性；候选尚未完整链接，没有执行候选 server 的大型项目性能或语义验收。探针用的是当前工作区源码，其中包含未提交的性能默认值调整。

## 如何加快采用正式版

1. **按官方稳定标签启动评估。** 固定发布 SHA，用已有 SDK Git 对象、离线依赖和真实项目输入，执行恢复试合、关键翻译单元编译及少量语言正反例。输出一个候选结论和需人工处理的语义点，不等待参考实现选择该版本。发行候选可用于提前发现接口变化，正式标签仍需重新确认。
2. **第一批只改 SDK 兼容性。** 先合并五处实现和四处测试，完成全量 SDK/server 构建及测试，检验补丁能在干净的官方 checkout 上重建。更新 gitlink、项目补丁、文件清单和默认 UVM 预解析制品；测试旧缓存失效、自定义配置一次生成及重启后复用。避免同期修改补全策略或缓存默认值。
3. **用候选 SDK 自身的原生分析做语义对照。** 验收 package 导出、宏重定义和跨文件保存、活动实例参数、泛型、取消、诊断顺序、旧诊断清除。对 5 个预期语言变化逐项说明。用参考实现的测试发现用例，由本项目定义冻结和增量模式的预期。
4. **最后进行跨版本性能验收。** 在同机同文件清单、相同开关与缓存限制下，对 OpenTitan 大型 SoC、CVA6 + UVM 和重宏验证工程运行当前版/候选版配对试验。分别记录冷启动、首次查询和诊断、连续编辑、结构回退和峰值 RSS。诊断正确、打包恢复正常且关键路径没有可重复的退步，再单独发布 SDK 升级。时间目标可定为正式版发布后一个工作日内给出初筛结论；发布日期取决于以上结果。
