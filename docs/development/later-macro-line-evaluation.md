# 后续方法宏行号的局部诊断证明

候选基于 main `8489d8f2810b5e9546e66cd220511d1ad7ad4a2f`，二进制 SHA256 `9d4c554518594189f6baae86c48364e53ab49a4aedde77092e71fb51eec1eac8`。
所有相关实验仍默认关闭；无新增固定防抖。五类总目标仍 active。

原始 CVA6 完整验证环境中，在 build_phase 插入多行局部声明、get_name 和 uvm_info 后，
后续两个方法的日志宏行号会改变，旧版本因此执行完整诊断。本轮用受限的展开证明消除这个回退：
逐个以各自原始宏环境重新解析相邻方法，CST token 必须完全一致，仅允许内建 __LINE__ 改变
普通非静态 void 类函数的完整 signed-int 输入实参。原语义、driver、时序及引用贡献保持有效，
位置通过原有 source projection 换算。不会重新绑定整个 retrieve_vif，也没有放宽层次或虚接口边界。

原生 AST 证明实参是完整的 int32 字面量；formal 也必须为 signed int32，当前值必须非负且在范围内。
新旧 token 的 kind/rawText、内建宏来源、解析边界、语法诊断和外部 elaboration 依赖均需检查。
每个方法恢复自己的 keyword、宏定义日志、logical line 和 warning pragma。内建宏不在 macroRefs 中，
因此也检查直接 intrinsic 使用。展开中有状态/条件宏、token 拼接或不明上下文即回 Native。
编辑体里的嵌套宏和宏参数同样不能隐藏 define/undef/其他预处理状态改变。

悬停/补全文档遇到包住编辑体或位于其后的旧声明时，通过当前 Native 语法展示，避免旧展开行号和链接。
当前局部符号不按旧偏移二次换算。普通编辑体内悬停仍使用局部编译；后续声明的文档不是本轮快速路径。
原生代码展示在局部证书内完成并最终重新验证，不使此前返回的补全票据失效。
取消期间不发布部分诊断，并能用原完整基线重试。

## 同场景测量

原始多行前缀是主场景，单行仅为控制。以 100ms 独立输入衡量入队到响应，包含不完整表达式和错误符号。
